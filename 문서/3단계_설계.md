# 3단계. 실험 설계와 실행

이 설계는 데이터를 모으기 전에 확정한 것이다. 다만 `## 4`의 같은 원두 판단 규칙은 30회를 모은 뒤, 겹침을 계산하기 전에 확정했다. 바뀐 것은 맨 아래 "설계 변경 기록"에 언제, 무엇을, 왜 바꿨는지 적는다.

## 1. 실험 설계 표

| 항목 | 내용 |
|---|---|
| 실험 방법 | AI에게 같은 요청을 문장 표현만 바꿔 여러 번 보내고, 추천된 원두 목록을 기록한다 |
| 사용하는 AI | Claude (실행 때 화면에 표시된 모델 이름을 기록에 함께 적는다) |
| 바꾸는 조건 | 취향을 말하는 문장 표현 3종 (A. 구체적 서술, B. 짧은 키워드, C. 비유적 표현) |
| 반복 횟수 | 문장마다 10회 |
| 표본 수 | 3종 × 10회 = 30회 (원자료는 30건이어야 한다) |

문장 3종의 내용은 `1단계_가설.md`의 `## 5. 측정 방법`에 있는 문장을 그대로 쓰며, 실행 중 바꾸지 않는다.

## 2. 바꾼 조건과 고정한 조건

| 구분 | 조건 | 값 |
|---|---|---|
| 바꾸는 조건 | 문장 표현 | A, B, C |
| 고정 조건 | 취향의 5개 요소 | 강한 산미, 꽃향, 시트러스 계열 과일향, 긴 여운, 약한 쓴맛 |
| 고정 조건 | 요청 문장 | "원두를 5가지 추천해 주세요" |
| 고정 조건 | 추천 개수 | 5개 |
| 고정 조건 | 대화 | 매 요청마다 새 대화를 열고, 대화 하나에 요청 하나만 보낸다. 추가 질문이나 다시 생성하기는 쓰지 않는다 |
| 고정 조건 | 기억 기능 | 평소 쓰는 계정이라 기억 기능은 끄지 않고, 30회 모두 비공개(incognito) 대화에서 보낸다. 공식 안내(Claude 고객센터 "Use incognito chats")에 비공개 대화는 기존 기억을 쓰지 않고 기억에 저장되지도 않는다고 적혀 있다 |
| 고정 조건 | 프로필 설정 | 같은 안내에 비공개 대화에서도 프로필 설정은 Claude가 쓸 수 있다고 적혀 있다. 그래서 30회 동안 프로필 설정을 바꾸지 않으며, 이 점을 논문의 한계에 적는다. 실제로 응답 3개(요청 13, 15, 20)에 "대구"라는 지역 언급이 나왔다. 질문에는 지역 정보가 없었다 |
| 고정 조건 | 웹 검색 | 비공개 대화 화면의 + 메뉴(파일 업로드, Skills, 커넥터, 플러그인 추가, 리서치)에 웹 검색을 끄는 항목이 없었다. 끌 수 없으므로, 응답에 웹 검색을 한 표시가 있었는지 요청마다 기록한다 |
| 고정 조건 | 추가 기능 | "리서치", 커넥터, Skills, 플러그인, 파일 첨부는 쓰지 않는다 |
| 고정 조건 | 프로젝트 | 프로젝트 안이 아닌 일반 대화에서 보낸다 |
| 고정 조건 | 사용하는 모델 | Claude Sonnet 5.5, 모델 이름 옆 설정은 "중간"으로 30회 모두 같게 둔다 (비공개 대화 화면에서 확인) |

## 3. 측정하는 값

- 요청 한 번의 응답에서 추천된 원두 5개를 적는다.
- 원두마다 네 항목으로 나눠 기록한다: 생산국, 세부 지역, 품종, 가공 방식. 적혀 있지 않은 항목은 빈칸으로 둔다. 농장 이름(예: 게이샤 빌리지)은 세부 지역 칸에 적는다.
- 항목 값은 응답의 제목 줄(번호가 붙은 줄)에 적힌 것만 쓴다. 설명 문장에만 나온 내용은 쓰지 않는다.
- 응답 원문 전체도 그대로 저장한다.
- 응답에 가공 방식을 적었는지도 원두마다 기록한다.

## 4. 같은 원두를 판단하는 규칙

확정일: 2026-11-01 (30회 수집을 마친 뒤, 겹침을 계산하기 전). 확정 경위는 맨 아래 "설계 변경 기록"에 적었다.

**주 규칙**

1. 두 원두를 생산국, 세부 지역, 품종, 가공 방식 네 칸으로 비교한다.
2. 두 쪽 모두에 적힌 칸만 비교한다. 한쪽이라도 비어 있으면 그 칸은 건너뛴다.
3. 한 칸에 값이 둘 이상이면(" / "로 이어 적음) 하나라도 상대와 겹치면 그 칸은 같다.
4. 비교한 칸이 모두 같으면 같은 원두이고, 하나라도 다르면 다른 원두다.
5. 예외 하나: 한쪽에만 품종이 적혀 있으면 다른 원두로 본다. (이유: 에티오피아 게이샤와 에티오피아 예가체프를 건너뛰기 규칙만 쓰면 나라만 비교해서 같다고 나오기 때문이다.)
6. 등급(AA, G1 등), 로스팅 정도, 표기 언어(한글, 영어), 표기 차이(게샤와 게이샤, 시다마와 시다모, 예가체페와 예가체프)는 무시한다.
7. 두 응답의 겹침은 일대일로 센다. 한 원두는 상대 응답의 원두 하나와만 짝이 될 수 있고, 짝이 가장 많아지게 짝을 지어 센다. 0에서 5 사이의 정수다.

**보조 규칙(결과가 규칙에 좌우되는지 확인용)**

- 원문 표기에서 정리한 이름(생산국, 세부 지역, 품종, 가공 방식을 이은 값)이 완전히 같을 때만 같은 원두로 본다. 빈칸도 값으로 취급한다.
- 주 규칙과 보조 규칙의 결론(A-B, A-C, B-C 각각 "비슷하다"인지 "달라졌다"인지)이 같으면 규칙과 무관한 결과로 적고, 다르면 어느 쌍에서 다른지를 결과에 그대로 적는다.

**알려진 한계**

- 제목 줄에 품종이 괄호 안에 적힌 경우(요청 13, 22, 27의 부르봉, SL28 표기)도 품종으로 기록했으므로, 5번 예외 때문에 같은 나라의 평범한 항목과 다른 원두로 판정된다. 해당 항목은 150개 중 3개다.
- 한 항목에 두 나라나 두 품종이 묶여 있는 경우(예: "파나마 또는 콜롬비아 게이샤")는 3번 규칙대로 하나라도 겹치면 같다고 보므로, 덜 구체적으로 적힌 항목일수록 같다고 판정되기 쉽다.
- 예가체프 안의 마을(코체레, 게뎁, 아리차)과 게이샤 빌리지처럼, 지역 이름이 서로 겹치는 경우를 AI가 섞어 쓴다. 제목 줄에 적힌 이름을 그대로 기록했다.

## 5. "비슷하다"를 판단하는 규칙

1. 기준선: 같은 문장으로 보낸 10개 응답에서 가능한 모든 쌍(문장마다 45쌍)의 겹침 개수를 평균낸다. 문장 A, B, C 각각 구한다.
2. 표현 간 겹침: 문장 A와 B(100쌍), A와 C(100쌍), B와 C(100쌍)의 겹침 개수를 쌍마다 평균낸다.
3. 판단: 표현 간 평균 겹침이 두 문장의 기준선 평균보다 0.5개 이상 낮으면 "달라졌다", 그보다 덜 낮으면 "비슷하다"로 한다. A-B, A-C, B-C 세 쌍을 각각 판단한다.
4. 가설 판정: 세 쌍이 모두 "비슷하다"이면 가설을 지지한다. 하나라도 "달라졌다"이면, 어느 쌍에서 달라졌는지를 결과로 적는다.
5. 이 기준(0.5개)은 데이터를 모으기 전에 정했다. 결과를 보고 바꾸지 않는다.

## 6. 보내는 순서

같은 문장이 몰려서 시간에 따른 영향이 한 문장에만 쏠리지 않도록, 3문장을 돌려가며 보낸다. 10번째 라운드는 첫 번째 라운드와 같다.

| 라운드 | 순서 | 라운드 | 순서 |
|---|---|---|---|
| 1 | A, B, C | 6 | C, A, B |
| 2 | B, C, A | 7 | A, B, C |
| 3 | C, A, B | 8 | B, C, A |
| 4 | A, B, C | 9 | C, A, B |
| 5 | B, C, A | 10 | A, B, C |

## 7. 시험 실행

본 실험 전에 문장 A로 2회 시험 삼아 보내서, 기록 방식에 빠진 것이 없는지 확인한다. 시험 실행의 응답은 본 데이터 30건에 포함하지 않고 별도 파일에 보관한다. 시험 실행 후 기록 방식을 바꾸면 "설계 변경 기록"에 적는다.

## 8. 기록 방식

- 응답 원문: 요청마다 하나씩 텍스트로 저장한다 (`raw/01_A.txt`처럼 번호와 문장 이름으로 된 이름).
- 정리표: `data.csv` 한 개에 한 줄이 원두 하나다. 열은 요청번호, 라운드, 문장, 날짜와 시간, 모델, 대화 방식(비공개 대화 여부), 사용 PC, 원두 순번, 원문 표기, 생산국, 세부 지역, 품종, 가공 방식, 가공 방식 적힘, 웹 검색 표시, 비고, 분류 확인이다. 원문에서 분류표를 만드는 과정은 `scripts/build_data.py`에 있고, 이 스크립트가 분류표의 값이 원문 제목 줄에 실제로 있는지 검사한다.
- 한 요청은 5줄이고, 전체는 30 × 5 = 150줄이다.

## 9. 확인 방법

- 요청번호가 1~30까지 빠짐없이 있고, 문장 A, B, C가 각각 10건인지 센다.
- `data.csv`의 줄 수가 150인지 센다.
- 원문 파일이 30개인지 센다.
- 위 세 숫자가 맞는지는 실행 스크립트로 확인한다.

## 10. 설계 변경 기록

설계를 바꾼 것은 아래와 같다. 바꾸는 것이 생기면 이 표에 이어서 적는다.

| 시점 | 바꾼 것 | 이유 |
|---|---|---|
| 시험 실행 2회 후, 본 데이터 수집 전 (2026-10-30) | `## 4`에 "한 항목에 지역이나 나라가 둘 이상이면 하나라도 같을 때 같은 것으로 본다" 규칙을 추가함. 정리표에 `비고` 열을 둠 | 시험 응답에 "구지 / 시다모", "르완다 또는 부룬디"처럼 한 항목에 둘 이상이 적힌 경우가 있었는데 기존 규칙에 이를 다루는 내용이 없었다. AI가 둘을 적는 순서에 결과가 좌우되지 않도록 ②(하나라도 같으면 같음)를 작성자가 선택했다 |
| 30회 수집 후, 겹침 계산 전 (2026-11-01) | `## 4` 규칙을 확정함. (1) 비교 칸을 생산국, 세부 지역, 가공 방식 세 칸에서 품종을 더한 네 칸으로 늘림. (2) 두 쪽 모두에 적힌 칸만 비교하는 건너뛰기 규칙을 넣음. (3) 한쪽에만 품종이 적혀 있으면 다른 원두로 보는 예외를 넣음. (4) 일대일로 세는 방식을 정함. (5) 보조 규칙을 "나라, 지역, 가공 방식이 모두 적히고 같아야 함"에서 "정리한 이름이 완전히 같을 때만 같음"으로 바꿈. (6) 정리표에 품종과 사용 PC 열을 더함. | 시험 실행에서 쓰지 못한 응답 형태가 본 데이터에서 나왔다. 응답 제목에 등급(AA, G1), 품종(게이샤), 농장 이름(게이샤 빌리지)이 지역과 섞여 적혀서 세 칸으로는 판단이 안 맞았다. 확정 전에 점검해 보니 건너뛰기 규칙만 쓰면 에티오피아 게이샤와 예가체프가 같다고 나오는 문제와, 이전 보조 규칙이 똑같은 이름도 다르다고 하는 문제가 있어서 (3)과 (5)를 넣었다. 이 규칙은 30회를 모두 모은 뒤에 정했다. 다만 겹침 숫자는 규칙을 확정하기 전에는 하나도 계산하지 않았다 |

시험 실행 2회의 응답과 정리표는 `pilot` 폴더에 있으며 본 데이터 30건에 포함하지 않는다. 시험 실행에서는 응답 10개 항목 모두 가공 방식(워시드)이 적혀 있었다.
